# 🛰️ ARIA v9.5 — The Resilience Monitor
**NTU Remote Sensing & Spatial Information Analysis | Week 14 Project**

本專案將遙測分析系統 ARIA 升級至 v9.5（韌性監測引擎），結合跨世代 Landsat 多衛星（L5/L7/L8/L9）的波段調和，將分析時間軸擴展至 **26年（2000–2026）**。專案主要涵蓋太魯閣研究區的「植被長期演替與災後韌性評估」，以及桃園台地「埤塘水體變遷偵測」，並展示了如何處理大規模雲端運算的效能瓶頸。

---

## 🏗️ 1. 系統工作架構說明 (System Architecture)

本專案的工作流涵蓋了資料前處理、時序運算、空間統計與進階視覺化，分為以下四大核心任務與三大加分擴充：

### 🔹 核心任務 (Core Tasks)
* **Task 1: Landsat 波段調和與長時序建置 (Band Harmonization)**
  * **模組說明：** 將 2000-2026 年間的 L5/L7 影像校正至 L8/L9 基準，建立跨代無縫接軌的 `ImageCollection`，套用雲遮罩後計算年度中位數 NDVI，建構了長達 26 年的地景基期。
* **Task 2: 像素級線性趨勢分析 (Pixel-Level Linear Trend)**
  * **模組說明：** 利用 `ee.Reducer.linearFit()` 針對每一個像元計算 26 年的 NDVI 變動斜率（Slope），突破傳統全區平均的盲點。我們透過 JRC 全球地表水遮罩剔除海洋與立霧溪的雜訊，產出高解析度的綠化 (Greening) 與退化 (Browning) 趨勢空間圖。
* **Task 3: 桃園埤塘變遷與 MNDWI 偵測驗證 (Pond Disappearance)**
  * **模組說明：** 聚焦桃園台地，對比早期 (2000-2005) 與近期 (2021-2026) MNDWI 影像。結合 DEM 陸地遮罩去除西部海岸線的潮汐雜訊後，精算消失與新增埤塘面積，並透過 223 口已知埤塘普查點位進行取樣驗證，最終達成 **89.2%** 的準確偵測率。
* **Task 4: 強震植被韌性評估 (Vegetation Resilience Metrics)**
  * **模組說明：** 針對 2024 年花蓮大地震，擷取「震前基期 (2020-2024.03)」、「震後衝擊 (2024.04-12)」與「復育期 (2025-2026)」三個時間段。計算植被恢復率 (Recovery Ratio, RR)，嚴謹界定「持續退化、慢速恢復、恢復中、超越基期」四級，輔助水保工程的決策。

### 🚀 進階擴充 (Bonuses)
* **Bonus 1:** Multi-Index Dashboard (多指標儀表板) — 同步繪製 NDVI、MNDWI、NBR 26 年折線圖，交叉比對自然演替與災害極端衝擊。
* **Bonus 2:** 26-Year NDVI Timelapse — 生成年度動態 GIF，視覺化長時序的綠化過程與 2024 震後瞬間的崩塌。
* **Bonus 3:** Interactive Split-Panel — 建構互動式左右滑桿，精準對齊並比對 2024 地震前後的地表傷痕。

## 🛠️ 2. AI 診斷與除錯日誌 (AI Diagnosis Log)

在處理龐大的 26 年尺度、30 公尺全像素普查運算時，我們遭遇了多項 GEE (Google Earth Engine) 的經典限制與邏輯陷阱。以下為除錯與優化紀錄：

### 🛑 錯誤 1：GEE 記憶體超載與運算逾時
* **錯誤訊息：** `User memory limit exceeded` 及 `.getInfo()` 卡死。
* **發生情境：** 於 Task 2 (全區線性回歸比例統計) 及 Task 3 (桃園台地全區面積加總) 時，一次性請求數千萬像素的統計資訊。
* **AI 診斷與修復：**
  1. **導入分塊運算防爆機制：** 在所有 `.reduceRegion()` 統計中強烈要求加入 `tileScale=4`，迫使 Google 伺服器將大範圍區域切分為更小的 Tile 網格分批計算。
  2. **非同步匯出策略：** 將需要最精細 30m 解析度的 GeoTIFF 產製交給後台 `ee.batch.Export.image.toDrive()` 處理，確保不阻塞 Notebook 執行緒。

### 🛑 錯誤 2：直方圖統計結果為 0% (字典鍵值漂移)
* **發生情境：** Task 2 執行 `frequencyHistogram` 取得像素分類統計時，各類別加總數量為 0。
* **AI 診斷與修復：** GEE 傳回的 Histogram Dictionary 在不同運算環境中，Key 值會隨機呈現浮點數字串 (如 `'1.0'`) 或整數字串 (如 `'1'`)。撰寫了穩健的 `get_count()` 迴圈函數，透過字串包含比對 (`str(target_val) in key`)，成功防堵鍵值不匹配導致的 0 值錯誤。

### 🛑 錯誤 3：沿海雜訊與水體異常干擾植被/埤塘統計
* **發生情境：** 太魯閣東側的太平洋潮汐與河谷水體，造成 Task 2 / Task 4 植被變化的誤判；桃園西側海岸的潮汐漲退，導致 Task 3 埤塘變遷面積嚴重失真。
* **AI 診斷與修復：** 實施「雙重遮罩 (Dual Masking) 策略」：
  1. **太魯閣 (Task 2 & 4)：** 引入 `JRC/GSW1_4/GlobalSurfaceWater`，提取歷史最大水體範圍 (`max_extent`)，反轉生成 `non_water_mask`，精準刨除海域與常態水體。
  2. **桃園 (Task 3)：** 調用 USGS DEM 資料，篩選高程 `gt(0)` 建立 `land_mask` (陸地遮罩)，完美排除西部海岸線潮汐雜訊。

### 🛑 錯誤 4：植被韌性「持續退化」比例離奇歸零 (Clamp 陷阱)
* **發生情境：** Task 4 Part 2 重分類統計時，「🔴 持續退化 (RR < 0)」的比例為絕對的 `0.0%`。
* **AI 診斷與修復：** 經過程式碼逆向追蹤，發現官方預設的恢復率計算公式中包含了 `.clamp(0, 1.5)` 函數。該截斷機制在第一階段就把所有小於 0 的惡化像素強行歸零，導致後續 `< 0` 的重分類抓不到任何像素。**修復方案：** 將界限放寬為 `.clamp(-1.0, 1.5)`，徹底釋放負值潛能，成功還原出震後無力恢復的真實坡地衰退比例。

## 📊 3. 專案產出與結論
本系統成功完成了 W13 到 W14 從「照片到電影」的進化。我們證實了太魯閣在長達 26 年的歷史中具備高度自我復原的演替能力，但也同時透過 30m 精確統計，量化了 2024 年地震造成的不可逆邊坡破壞；並於桃園都會區展現了水體偵測的高度泛用性（近九成偵測率），為未來的災害評估與都市防洪韌性提供了極具價值的長期數據基底。
